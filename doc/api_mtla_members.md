# API участников МТЛА

`GET https://bsn.expert/api/mtla/members` возвращает связи Stellar-аккаунтов участников МТЛА с Telegram ID и username. Доступен полный список или выборка по Stellar-адресу и Telegram ID. API работает только на чтение.

## Получение ключа

1. Авторизуйтесь на [BSN Expert](https://bsn.expert) своим аккаунтом координатора.
2. Откройте [API-ключи](https://bsn.expert/preferences/api).
3. Укажите название ключа и включите «Участники МТЛА → Читать» (`mtla_members:read`). Если нужны только эти данные, отключите остальные разрешения.
4. Создайте ключ и сохраните его: он показывается один раз.

Каждый запрос должен содержать заголовок `Authorization: Bearer <API_KEY>`. В примерах ниже ключ уже задан в переменной окружения `BSN_API_KEY`.

## Запросы

Полный список:

```sh
curl -H "Authorization: Bearer ${BSN_API_KEY}" \
  'https://bsn.expert/api/mtla/members'
```

По Stellar-адресу. Задайте нужный полный адрес в переменной `STELLAR_ACCOUNT`:

```sh
curl -H "Authorization: Bearer ${BSN_API_KEY}" \
  "https://bsn.expert/api/mtla/members?stellar=${STELLAR_ACCOUNT}"
```

По Telegram ID; замените число на нужное:

```sh
curl -H "Authorization: Bearer ${BSN_API_KEY}" \
  'https://bsn.expert/api/mtla/members?telegram_id=123456789'
```

| Параметр | Формат | Результат |
| --- | --- | --- |
| `stellar` | Полный корректный Stellar-адрес: 56 символов, начинается с `G` | Не более одной записи |
| `telegram_id` | От 1 до 20 десятичных цифр, первая — от `1` до `9`; без знака и пробелов | Все аккаунты с этим Telegram ID |

Оба параметра необязательны.

## Ответ

Успешный запрос возвращает `200 OK` и JSON. Пример ответа с условными данными:

```json
{
  "status": "OK",
  "members": {
    "GAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAWHF": {
      "telegram_id": "123456789",
      "telegram_username": "example_user"
    }
  }
}
```

- `members` — объект, ключи которого являются Stellar-адресами. Формат одинаков с фильтрами и без них.
- `telegram_id` — строка.
- `telegram_username` — строка без `@` или `null`. Username может измениться; используйте Telegram ID для сопоставления пользователей.

Если совпадений нет, ответ успешный, а `members` — пустой объект:

```json
{"status": "OK", "members": {}}
```

## Проверка доступа

Достаточно координировать хотя бы одну [действующую программу МТЛА](https://bsn.expert/mtla/programs), для которой выполнены все условия:

- Официальный аккаунт МТЛА указывает на программу тегом `Program`.
- Программа указывает через `ProgramCoordinator` ровно на один уникальный аккаунт — владельца ключа.
- У владельца не менее 1 MTLAP, программа указывает на него через `MyPart`, а он на программу — через `PartOf`.

Если программа указывает на нескольких разных координаторов, она не даёт доступ ни одному из них.

Если ни одна программа больше не даёт право доступа, API возвращает `403`. Ключ и разрешение сохраняются, остальные разрешения продолжают работать. После восстановления статуса координатора тот же ключ снова получает доступ. Удаление ключа на странице настроек отзывает его полностью.

## Ошибки

| HTTP-код | Причина | Действие клиента |
| --- | --- | --- |
| `400` | Неверный формат `stellar` или `telegram_id` | Исправить параметры |
| `401` | Заголовок Bearer отсутствует или некорректен; ключ неверен либо удалён | Проверить заголовок и ключ |
| `403` | Нет `mtla_members:read` или владелец больше не проходит проверку координаторства | Проверить разрешение и связи программы; автоматические повторы не помогут до изменения прав |
| `405` | Метод не поддерживается | Использовать `GET` |
| `503` | Снимок данных недоступен | Повторить позже с паузой |

Ошибки `400`, `401`, `403` и `503`, сформированные этим API, возвращаются в JSON:

```json
{
  "status": "error",
  "message": "Invalid stellar or telegram_id filter"
}
```

Обрабатывайте HTTP-код, а `message` используйте для диагностики. Ошибка маршрутизации или веб-сервера может содержать HTML вместо JSON.

## Данные и ограничения

- Пагинации и выдачи изменений нет.

Для синхронизации локальной копии запрашивайте список без фильтров. После ответа `200` с корректным JSON применяйте его как новый снимок, включая удаление исчезнувших записей.

Для браузерных клиентов поддерживается CORS с любого origin: `OPTIONS` без ключа возвращает `204`, разрешены `GET`, `OPTIONS` и заголовок `Authorization`. Сам `GET` всегда требует ключ.
