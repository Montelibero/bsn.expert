# BSN.Expert

Обозреватель и редактор BSN данных, а также набор вспомогательных инструментов 
для работы с блокчейном Stellar для нужд, прежде всего, участников Ассоциации Монтелиберо.

## Концепция

Минималистичный no-js-first сервис. Часть данных берёт из bsn_crawler, часть подгружает в процессе.

## Запуск для разработки

1. Запустить хотя бы раз [bsn_crawler](https://github.com/Montelibero/bsn_crawler).
2. Создать `.env` на основе `.env.example`.
3. Запустить `docker compose up`.

### Проверки перед pull request

PHP-проверки запускаются из каталога `app` одной командой:

```bash
composer install
composer check
```

Она выполняет PHP lint, Twig lint, PHPStan, regression-тесты и проверку Composer security advisories. Проверка набора Font Awesome запускается из корня проекта командой `npm run fa_test`.

### Автоматические проверки перед коммитом

Один раз для каждого клона установите PHP-зависимости **с require-dev** (включая PHPStan), Node-зависимости и включите Git hook:

```bash
(cd app && composer install)
npm ci
npm run hooks:install
```

Нужны PHP и расширения из `app/composer.json`, Composer, Node.js из `.nvmrc` и npm. Git-клиент, включая GUI, должен видеть эти программы в `PATH`. После изменения `composer.lock` или `package-lock.json` обновите локальные зависимости через `composer install` или `npm ci`.

Теперь `git commit` запускает `composer validate --strict`, `composer check` и `npm run fa_test`. Любая ошибка блокирует коммит; вывод проверки показывает причину. Для проверки без коммита используйте `npm run check:staged`.

Успешные этапы выводят короткий статус. При ошибке хук показывает последние 25 строк вывода неудачного этапа и путь к полному логу во временном каталоге. Этот лог сохраняется после удаления проверенной копии. Сообщения, которые тесты намеренно создают при проверке ошибочных ситуаций, не засоряют вывод успешной проверки.

Хук проверяет отдельную временную копию **индекса Git**: только файлы и части изменений, выбранные для коммита. Незакоммиченные исправления и не добавленные в Git файлы не смогут скрыть ошибку. Рабочая папка и индекс не изменяются, `stash` не используется. Локальные зависимости переиспользуются, PHP autoloader пересоздаётся в копии. Проверка самого механизма хука: `npm run test:hooks`.

При частичном коммите в IDE выбирайте согласованный набор: изменение сигнатуры или поведения метода вместе с обновлением его тестов, шаблонов и переводов. Например, изменения обмена токенами в `AssetSwapController.php` требуют соответствующей версии `AssetSwapTokensTest.php`. Если в выбранной части `composer.json` добавлен запуск нового теста, сам файл теста тоже должен попасть в этот коммит.

Аудит зависимостей требует доступа к Packagist: ошибка загрузки advisories тоже блокирует коммит. Хук не собирает Docker и не заменяет CI: окружение сборки отличается, а сведения об уязвимостях могут обновиться после коммита. Git позволяет явно пропустить хук через `git commit --no-verify`; CI при этом продолжает выполнять проверки.

В pull request workflow дополнительно собирается production image и запускается изолированный HTTP route smoke с временными MongoDB и Memcached. Публикация образа разрешена только после успешного прохождения обоих CI jobs.

### MongoDB

- В docker-compose добавлен сервис `mongo` (порт `27017`, volume `mongo_data`). Обновите `.env` по образцу и поднимите контейнеры `docker compose up`.
- Быстрый доступ из терминала: `docker compose exec mongo mongosh -u "$MONGO_ROOT_USERNAME" -p "$MONGO_ROOT_PASSWORD"`.
- Индексы (`usernames`, `contacts`) создаются при старте контейнера `app` через `app/cli/mongo-indexes.php` (запуск из `init.sh`).

### API участников МТЛА

`GET https://bsn.expert/api/mtla/members` возвращает Telegram-связи участников МТЛА
по ключу действующего координатора программы. Получение ключа, фильтры, формат ответа
и ограничения описаны в [инструкции API участников МТЛА](doc/api_mtla_members.md).

После обновления приложения полный импорт связок появится при следующей штатной
синхронизации Grist.

Для данных о чатах укажите в `.env` ключ `TG_MEMBERS_KEY` от `https://tg-members.mtla.me`.
Раз в 15 минут `app-cron` обновляет в MongoDB состав доступных этому ключу групп и каналов.
При временном сбое API использует кеш в течение 24 часов после последней успешной
синхронизации. По истечении этого срока API возвращает `chats: null` и username из
Grist. Ответ `401` или `403` от `tg-members` отключает кеш сразу.

### Синхронизация с Grist

Grist webhooks используют существующие POST-адреса:

- `/tokens/reload_known_tokens`;
- `/mtla/reload_members`;
- `/documents/update_from_grist`.

Webhook только планирует полное обновление соответствующей таблицы. Каждое следующее событие переносит запуск ещё на 60 секунд; `app-cron` обрабатывает готовые задачи раз в минуту. Дополнительно раз в час планируется полная сверка всех трёх источников.

Для каждого Grist-документа предусмотрен отдельный bearer secret:

- `GRIST_WEBHOOK_SECRET_KNOWN_TOKENS`;
- `GRIST_WEBHOOK_SECRET_MTLA_MEMBERS`;
- `GRIST_WEBHOOK_SECRET_DOCUMENTS`.

Секрет задаётся в Grist в поле `Header Authorization` как `Bearer <secret>`. Пока соответствующая переменная окружения пуста, endpoint принимает webhook без проверки — это режим миграции, а не рекомендуемая постоянная конфигурация.

Операторы, чьи Stellar-аккаунты перечислены в `ADMINS`, могут посмотреть состояние синхронизаций и запустить любую из них немедленно на странице `/admin/caches/`.

### MCP-демо

Публичный read-only MCP доступен по единственному Streamable HTTP endpoint `POST /mcp`. Авторизация для демо не нужна. Сервер предоставляет три инструмента:

- `bsn.account.get` — публичная карточка аккаунта по Stellar-адресу или BSN username с краткой сводкой известных входящих и исходящих тегов;
- `bsn.account.tags` — полные входящие и исходящие теговые связи аккаунта, включая связанные аккаунты, неизвестные теги и статус ответной пары;
- `bsn.tags.list` — справочник тегов, категорий и правил парности.

Инструменты читают текущий снимок обозревателя, ничего не подписывают и не меняют. Сервер поддерживает stateless MCP `2026-07-28` и старые клиенты с `initialize` до `2025-11-25`. Для подключения MCP-клиенту достаточно URL endpoint.

Спецификация транспорта и инструментов: [MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http), [MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools).

Для агентов с поддержкой открытого формата Agent Skills в репозитории есть готовый навык [`bsn-expert`](.agents/skills/bsn-expert/SKILL.md). Он объясняет, как выбирать MCP-инструменты, трактовать направления и парность тегов и соблюдать границы публичного read-only сервера. Каталог навыка можно скопировать в проектный `.agents/skills/` или пользовательский `~/.agents/skills/` совместимого клиента. Сам `SKILL.md` не настраивает транспорт: агенту отдельно нужно подключить MCP endpoint `https://bsn.expert/mcp`.
